## 1. Prolog: Bayangkan Dunia Tanpa WiFi 🌍

Bayangkan kamu bangun pagi, ambil HP, tapi... **tidak ada WiFi**. 

- ❌ Tidak bisa streaming YouTube atau Netflix
- ❌ Tidak bisa main game online bersama teman
- ❌ Tidak bisa video call
- ❌ Smart home kamu mati total (lampu, AC, kamera semua offline)

**Ngeri, kan?** 😱

Nah, **IEEE 802.11** adalah "pahlawan tak terlihat" yang membuat semua itu mungkin. Standar inilah yang memungkinkan HP, laptop, smart TV, bahkan kulkas pintar kamu bisa "ngobrol" tanpa kabel.

> 🎓 **Fakta Menarik:** Nama "WiFi" sebenarnya tidak berarti apa-apa! Itu cuma merek dagang yang dibuat oleh Wi-Fi Alliance agar terdengar keren. Banyak orang mengira WiFi singkatan dari "Wireless Fidelity", tapi itu hanyalah **mitos**!

## 2. Bab 1: WiFi itu Apa Sih? 🤔

### 2.1. Sejarah Singkat

**Tahun 1997:**  
Bayangkan zaman di mana HP masih sebesar batu bata dan internet masih pakai kabel telepon yang berisik. Saat itu, sekelompok insinyur di **IEEE** (Institute of Electrical and Electronics Engineers) berpikir:

> *"Kenapa kita harus colok kabel terus? Bagaimana kalau perangkat bisa 'ngobrol' lewat udara?"*

Maka lahirlah **IEEE 802.11** — standar pertama WiFi dengan kecepatan **2 Mbps**.  
*(Cukup untuk kirim email teks, tapi jangan harap bisa streaming video!)* 🐌

**Tahun 1999:**  
Lahir **802.11b** dengan kecepatan **11 Mbps**. WiFi mulai populer! Laptop mulai punya antena WiFi built-in.

**Tahun 2003:**  
**802.11g** muncul dengan kecepatan **54 Mbps**. Cukup untuk streaming musik dan video kualitas rendah.

**Tahun 2009:**  
**802.11n (WiFi 4)** membawa revolusi: **MIMO** (Multiple Input Multiple Output) — pakai banyak antena sekaligus! Kecepatan melonjak ke **600 Mbps**.

**Tahun 2013:**  
**802.11ac (WiFi 5)** masuk era **Gigabit WiFi** dengan kecepatan **3.5 Gbps**. Streaming 4K jadi mungkin!

**Tahun 2019:**  
**802.11ax (WiFi 6)** fokus pada **efisiensi**. Bisa handle banyak perangkat sekaligus tanpa lemot.

**Tahun 2024:**  
**802.11be (WiFi 7)** datang dengan kecepatan gila-gilaan: **46 Gbps** dan teknologi **Multi-Link** (pakai 3 frekuensi sekaligus!).

### 2.2. Arsitektur WiFi: Siapa Saja yang Terlibat? 🏗️

Bayangkan WiFi seperti **sistem pos**:

```
┌─────────────────────────────────────────────────────┐
│                SISTEM POS WiFi                      │
├─────────────────────────────────────────────────────┤
│                                                     │
│   📱 HP/Laptop        📡 Access Point (AP)         │
│   (Pengirim Surat)    (Kantor Pos)                 │
│          │                    │                     │
│          │   "Ngobrol"        │                     │
│          └───── WiFi ─────────┘                     │
│                  │                                  │
│                  ▼                                  │
│           ┌──────────┐                              │
│           │   BSS    │  ← Basic Service Set         │
│           │ (1 AP +  │    (1 kantor pos +           │
│           │  client) │     beberapa pengirim)       │
│           └──────────┘                              │
│                  │                                  │
│                  ▼                                  │
│           ┌──────────┐                              │
│           │    DS    │  ← Distribution System       │
│           │ (Jaringan│    (Jaringan kabel           │
│           │  kabel)  │     yang menghubungkan       │
│           └──────────┘     semua kantor pos)        │
│                                                     │
└─────────────────────────────────────────────────────┘
```

**Komponen Utama:**
- **Station (STA):** Perangkat client (HP, laptop, smart TV)
- **Access Point (AP):** "Kantor pos" yang menghubungkan client ke jaringan
- **BSS (Basic Service Set):** 1 AP + beberapa client
- **ESS (Extended Service Set):** Beberapa BSS dengan nama (SSID) yang sama (untuk roaming)
- **DS (Distribution System):** Jaringan kabel backbone yang menghubungkan semua AP

---

### 2.3. Mode Operasi: Cara WiFi "Ngobrol" 💬

WiFi punya **4 mode operasi**, masing-masing seperti gaya komunikasi yang berbeda:

| Mode | Analogi | Penggunaan | Contoh |
|------|---------|------------|--------|
| **Infrastructure** | Client → AP → Internet | Rumah, kantor, kafe | HP kamu connect ke router rumah |
| **Ad-hoc (IBSS)** | Client ↔ Client (langsung) | Peer-to-peer, file sharing | Kirim file langsung antar laptop |
| **Mesh** | Multi-hop routing | Smart city, gedung besar | WiFi di mall yang luas |
| **Monitor** | Sniffing/packet capture | Security, forensik | Hacker (atau admin jaringan) intip traffic |

> 🔍 **Fakta:** Mode **Monitor** adalah mode "ninja" — kamu bisa melihat semua frame WiFi di udara, bahkan yang bukan untuk kamu! Ini yang dipakai tools seperti `airodump-ng` untuk analisis jaringan.

## 3. Bab 2: Anatomi Frame WiFi 📬

### 3.1. Frame WiFi = Amplop Surat

Bayangkan setiap paket data WiFi seperti **amplop surat**:

```
┌─────────────────────────────────────────────────────────────┐
│                    AMPLOP SURAT WiFi                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌─────────────┐  ┌──────────┐  ┌──────────┐  ┌─────────┐ │
│  │ Frame       │  │ Address 1│  │ Address 2│  │Address 3│ │
│  │ Control     │  │ (Tujuan) │  │ (Pengirim│  │ (BSSID/ │ │
│  │ (2 bytes)   │  │ (6 bytes)│  │  /BSSID) │  │  SA)    │ │
│  │             │  │          │  │ (6 bytes)│  │(6 bytes)│ │
│  └─────────────┘  └──────────┘  └──────────┘  └─────────┘ │
│                                                             │
│  ┌─────────────┐  ┌──────────────────────────┐  ┌────────┐ │
│  │ Sequence    │  │ Payload (Isi Surat)      │  │ FCS    │ │
│  │ Control     │  │ (Data yang dikirim)      │  │(Cek    │ │
│  │ (2 bytes)   │  │ (Variable length)        │  │ error) │ │
│  │             │  │                          │  │(4 bytes│ │
│  └─────────────┘  └──────────────────────────┘  └────────┘ │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**Penjelasan Setiap Field:**

| Field | Ukuran | Fungsi | Analogi |
|-------|--------|--------|---------|
| **Frame Control** | 2 bytes | Tentukan jenis frame (Management/Control/Data) & flags | "Jenis surat: biasa, terdaftar, atau kilat" |
| **Duration / ID** | 2 bytes | Reservasi waktu kanal udara (NAV) | "Estimasi waktu bicara agar orang lain tidak menyela" |
| **Address 1** | 6 bytes | MAC Tujuan Langsung (Receiver / RA / DA) | "Kepada: HP Budi" |
| **Address 2** | 6 bytes | MAC Pengirim Langsung (Transmitter / TA / SA) | "Dari: AP Router" |
| **Address 3** | 6 bytes | BSSID / Pengirim Awal / Tujuan Akhir | "Alamat kantor pos atau pengirim asli" |
| **Sequence Control** | 2 bytes | Nomor urut & fragmentasi frame | "Surat bagian 1 dari 3, nomor seri #1024" |
| **Address 4 (Opsional)**| 6 bytes | Digunakan pada WDS (AP-to-AP Mesh) saat To DS=1 & From DS=1 | "Jalur antar kantor pos ekspedisi" |
| **Payload** | Variable | Data informasi frame (IEs atau data IP/TCP/UDP) | "Isi surat sesungguhnya" |
| **FCS** | 4 bytes | Frame Check Sequence (CRC32 deteksi error) | "Cap stempel segel: pastikan isi surat tidak rusak" |

### 3.2. Frame Control Field: "Kepala Surat" 📝

Frame Control adalah 16 bit (2 byte) yang menentukan **jenis frame dan instruksinya**:

```
┌────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│                                       FRAME CONTROL (16 BITS)                                          │
├────────────────────────────────────────┬───────────────────────────────────────────────────────────────┤
│            BYTE 0 (Bit 0 - 7)          │                     BYTE 1 (Bit 8 - 15)                       │
├────────────┬──────────┬────────────────┼───────┬─────────┬──────┬───────┬───────┬──────┬──────────┬────┤
│ Bit 0 - 1  │ Bit 2 - 3│   Bit 4 - 7    │ Bit 8 │  Bit 9  │Bit 10│Bit 11 │Bit 12 │Bit 13│  Bit 14  │B15 │
├────────────┼──────────┼────────────────┼───────┼─────────┼──────┼───────┼───────┼──────┼──────────┼────┤
│  Protocol  │   Type   │    Subtype     │ To DS │ From DS │ More │ Retry │ Power │ More │Protected │Ord-│
│  Version   │ (00/01/  │  (Beacon/Probe/│       │         │ Frag │       │ Mgmt  │ Data │  Frame   │ er │
│    (00)    │  10/11)  │   Auth/Assoc)  │       │         │      │       │       │      │  (WPA)   │    │
└────────────┴──────────┴────────────────┴───────┴─────────┴──────┴───────┴───────┴──────┴──────────┴────┘
```

**Type (Bit 2-3):**
- `00` = **Management Frame** (Beacon, Probe, Auth, Assoc, Deauth)
- `01` = **Control Frame** (RTS, CTS, ACK)
- `10` = **Data Frame** (Payload data internet)
- `11` = Dipesan (Reserved)

**Subtype (Bit 4-7 untuk Management Frame):**
- `0000` (`0x0`) = Association Request
- `0001` (`0x1`) = Association Response
- `0100` (`0x4`) = Probe Request
- `0101` (`0x5`) = Probe Response
- `1000` (`0x8`) = Beacon Frame (paling terkenal di WiFi!)
- `1011` (`0xB`) = Authentication
- `1100` (`0xC`) = Deauthentication (pemutus koneksi)

## 5. Bab 4: Evolusi WiFi 🚀

### 5.1. Dari 2 Mbps sampai 46 Gbps!

| Generasi | Standar | Tahun | Kecepatan Max | Fitur Utama | Analogi |
|----------|---------|-------|---------------|-------------|---------|
| **WiFi 1** | 802.11 | 1997 | 2 Mbps | Standar pertama | "Sepeda onthel" 🚲 |
| **WiFi 2** | 802.11b | 1999 | 11 Mbps | Populer pertama | "Sepeda gunung" 🚵 |
| **WiFi 3** | 802.11g | 2003 | 54 Mbps | Pengganti b | "Motor bebek" 🏍️ |
| **WiFi 4** | 802.11n | 2009 | 600 Mbps | MIMO, Dual-band | "Motor sport" 🏎️ |
| **WiFi 5** | 802.11ac | 2013 | 3.5 Gbps | MU-MIMO, Beamforming | "Mobil keluarga" 🚗 |
| **WiFi 6** | 802.11ax | 2019 | 9.6 Gbps | OFDMA, TWT | "Mobil sport" 🏎️💨 |
| **WiFi 7** | 802.11be | 2024 | 46 Gbps | Multi-link, 320MHz | "Pesawat jet" ✈️ |

---

### 5.2. Teknologi Kunci per Generasi

**WiFi 4 (802.11n) — MIMO:**  
Bayangkan kamu punya **4 tangan** sekaligus untuk mengirim dan menerima data. Itulah **MIMO** (Multiple Input Multiple Output) — pakai banyak antena untuk meningkatkan kecepatan dan jangkauan.

**WiFi 5 (802.11ac) — MU-MIMO & Beamforming:**  
- **MU-MIMO:** AP bisa ngobrol dengan **banyak client sekaligus** (bukan satu per satu).
- **Beamforming:** AP "fokus" sinyal ke arah client tertentu (seperti senter yang diarahkan, bukan lampu ruangan).

**WiFi 6 (802.11ax) — OFDMA & TWT:**  
- **OFDMA:** Channel WiFi dibagi jadi **sub-channel kecil** (seperti jalan raya yang dibagi jadi banyak lajur). Banyak client bisa kirim data bersamaan tanpa tabrakan!
- **TWT (Target Wake Time):** Perangkat "tidur" sampai waktunya kirim data. Hemat baterai! 🔋

**WiFi 7 (802.11be) — Multi-Link & 320 MHz:**  
- **Multi-Link:** Pakai **3 frekuensi sekaligus** (2.4 GHz + 5 GHz + 6 GHz). Seperti punya 3 jalan tol paralel!
- **320 MHz Channel:** Lebar channel 2x lebih besar dari WiFi 6. Kecepatan gila-gilaan!

## 6. Bab 5: Channel WiFi 📻

### 6.1. Channel 2.4 GHz: "Jalan Raya yang Ramai" 🚗

Channel 2.4 GHz seperti **jalan raya dengan 14 lajur**, tapi hanya **3 lajur yang tidak saling tumpang tindih**: **1, 6, dan 11**.

```

├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Ch1 (2.412)  ████████████  ✅ Gunakan                     │
│  Ch2 (2.417)   ████████████  ❌ Overlap                    │
│  Ch3 (2.422)    ████████████  ❌ Overlap                   │
│  Ch4 (2.427)     ████████████  ❌ Overlap                  │
│  Ch5 (2.432)      ████████████  ❌ Overlap                 │
│  Ch6 (2.437)       ████████████  ✅ Gunakan                │
│  Ch7 (2.442)        ████████████  ❌ Overlap               │
│  Ch8 (2.447)         ████████████  ❌ Overlap              │
│  Ch9 (2.452)          ████████████  ❌ Overlap             │
│  Ch10 (2.457)          ████████████  ❌ Overlap            │
│  Ch11 (2.462)           ████████████  ✅ Gunakan           │
│  Ch12 (2.467)            ████████████  ⚠️ Terbatas         │
│  Ch13 (2.472)             ████████████  ⚠️ Terbatas        │
│  Ch14 (2.484)              ████████████  ⚠️ Jepang only    │
│                                                             │
│  Channel yang tidak overlap: 1, 6, 11                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**Kenapa hanya 1, 6, 11?**  
Karena setiap channel punya lebar **22 MHz**, tapi jarak antar channel hanya **5 MHz**. Jadi kalau kamu pakai channel 1 dan 2, mereka akan **saling mengganggu** (overlap).

> 🎯 **Tips:** Kalau router kamu di 2.4 GHz, **selalu pakai channel 1, 6, atau 11**. Jangan pakai channel lain!

---

### 6.2. Channel 5 GHz: "Jalan Tol yang Lebih Sepi" 🛣️

5 GHz punya **lebih banyak channel** dan **lebih sedikit interferensi** (karena tidak banyak perangkat yang pakai frekuensi ini).

| Channel | Frekuensi | DFS | Rekomendasi |
|---------|-----------|-----|-------------|
| 36, 40, 44, 48 | 5.180 - 5.240 GHz | Tidak | ✅ Gunakan |
| 52 - 144 | 5.260 - 5.720 GHz | Ya (Radar) | ⚠️ DFS (hindari kalau bisa) |
| 149 - 165 | 5.745 - 5.825 GHz | Tidak | ✅ Gunakan |

**Apa itu DFS?**  
DFS (Dynamic Frequency Selection) adalah fitur yang membuat router **otomatis pindah channel** kalau mendeteksi sinyal radar (misalnya dari bandara atau militer). Jadi kalau kamu pakai channel DFS, WiFi kamu bisa **tiba-tiba putus** kalau ada radar aktif! 😱

---

### 6.3. Channel 6 GHz: "Jalan Tol Baru yang Kosong" 🆕

6 GHz adalah **frekuensi baru** untuk WiFi 6E dan WiFi 7. Punya **59 channel** yang semuanya **bebas interferensi** (karena belum banyak perangkat yang pakai).

| Channel | Frekuensi | Keterangan |
|---------|-----------|------------|
| 1 - 233 | 5.925 - 7.125 GHz | Baru, banyak channel, bebas DFS |

> 🚀 **Fakta:** 6 GHz seperti **jalan tol baru yang masih sepi** — kamu bisa ngebut tanpa takut macet!

## 7. Bab 6: Keamanan WiFi 🔒

### 7.1. Evolusi Keamanan: Dari yang Rapuh sampai yang Tangguh

```
WEP (1997)  → 🔴 TIDAK AMAN (bisa di-crack dalam hitungan menit!)
    ↓
WPA (2003)  → 🟡 Kurang aman (TKIP, masih ada celah)
    ↓
WPA2 (2004) → 🟢 AMAN (AES) - STANDAR SAAT INI
    ↓
WPA3 (2018) → 🟢 LEBIH AMAN (SAE, GCMP)
```

---

### 7.2. WEP: "Gembok dari Kertas" 📄

**WEP (Wired Equivalent Privacy)** adalah standar keamanan pertama WiFi. Tapi sayangnya, WEP **sangat lemah** dan bisa di-crack dalam **hitungan menit** dengan tools seperti `aircrack-ng`.

**Kenapa WEP lemah?**  
WEP menggunakan algoritma **RC4** dengan **Initialization Vector (IV)** yang terlalu pendek (24 bit). Akibatnya, IV cepat berulang, dan hacker bisa mengumpulkan cukup data untuk memecahkan kunci.

> ❌ **JANGAN PAKAI WEP!** (Sudah usang sejak 2004)

---

### 7.3. WPA/WPA2: "Gembok Besi" 🔐

**WPA (Wi-Fi Protected Access)** datang sebagai pengganti WEP. WPA menggunakan **TKIP** (Temporal Key Integrity Protocol) yang lebih aman, tapi masih ada celah.

**WPA2** (2004) membawa **AES (Advanced Encryption Standard)** — algoritma enkripsi yang sama dengan yang dipakai oleh pemerintah AS untuk data rahasia!

**WPA2-PSK (Pre-Shared Key):**  
Kamu masukkan password, dan router menggunakan password itu untuk enkripsi. **Aman untuk rumah**, tapi kalau password kamu lemah (misalnya "12345678"), hacker bisa **brute force**.

**WPA2-Enterprise:**  
Pakai server **RADIUS** untuk autentikasi. Setiap user punya username dan password sendiri. **Sangat aman**, dipakai di kantor dan universitas.

> ✅ **WPA2 masih aman** (tapi pakai password yang kuat!)

---

### 7.4. WPA3: "Gembok Titanium" 💎

**WPA3** (2018) adalah standar keamanan terbaru. Fitur utamanya:

- **SAE (Simultaneous Authentication of Equals):**  
  Proses handshake yang **tahan terhadap brute force**. Bahkan kalau password kamu lemah, hacker tidak bisa menebak-nebak!

- **GCMP (Galois/Counter Mode Protocol):**  
  Enkripsi yang lebih kuat dari AES-CCMP (yang dipakai WPA2).

- **Forward Secrecy:**  
  Bahkan kalau hacker berhasil mencuri password kamu, mereka **tidak bisa mendekripsi data yang sudah dikirim sebelumnya**.

> ✅ **WPA3 adalah yang terbaik saat ini!**

---

### 7.5. Serangan WiFi Umum 🕵️

| Serangan | Deskripsi | Cara Mencegah |
|----------|-----------|---------------|
| **Evil Twin** | AP palsu yang meniru SSID & MAC AP asli | Jangan connect ke SSID terbuka mencurigakan; gunakan WPA3-Enterprise & 802.1X certificate |
| **Deauth Attack** | Kirim frame deauth palsu untuk memutuskan koneksi paksa | Aktifkan **802.11w / PMF (Protected Management Frames)** atau beralih ke WPA3 |
| **KRACK (Key Reinstallation)** | Eksploitasi 4-way handshake WPA2 | Update patch firmware OS & router |
| **Brute Force / Dictionary** | Tebak passphrase WPA2 dari 4-way handshake offline | Gunakan passphrase panjang (>16 karakter acak) atau WPA3-SAE |
| **Karma / Rogue AP** | AP nakal yang merespons setiap probe request client | Matikan auto-connect ke open network di HP/laptop; gunakan VPN |

#### 🛡️ Bedah Kasus: Mengapa Deauthentication Attack Begitu Terkenal?
Pernahkah kamu penasaran, mengapa seorang pentester (atau hacker) bisa memutuskan koneksi laptopmu dari router tanpa tahu password WiFi-nya?

1. **Akar Masalah (Legacy 802.11):**
   Pada standar 802.11 versi awal hingga WPA2 standar, **hanya Data Frames yang dienkripsi**. Frame Management (seperti *Deauthentication* `0xC000` dan *Disassociation* `0xA000`) dikirimkan secara terbuka (*plaintext*) tanpa tanda tangan digital.
2. **Kelemahan Udara:**
   Karena media nirkabel adalah udara terbuka (*broadcast medium*), siapa pun bisa membuat paket raw palsu dengan field Address 2 (pengirim) diisi MAC router asli. HP korban yang menerima frame ini mengira routernya yang menyuruh putus!
3. **Penyelamat: IEEE 802.11w / PMF (Protected Management Frames):**
   IEEE merilis standar **802.11w**, di mana frame Management dilindungi dengan cryptographic integrity tag. Pada **WPA3, PMF bersifat WAJIB**. Jika ada yang mengirimkan Deauth palsu, sistem klien langsung menolaknya.

## 8. Bab 7: WiFi 6 & 7 🚀

### 8.1. WiFi 6 (802.11ax): "WiFi yang Pintar" 🧠

WiFi 6 bukan cuma soal kecepatan, tapi **efisiensi**. Bayangkan WiFi 6 seperti **sistem lalu lintas pintar** yang bisa mengatur banyak mobil sekaligus tanpa macet.

**Fitur Utama:**

| Fitur | Deskripsi | Benefit |
|-------|-----------|---------|
| **OFDMA** | Bagi channel jadi sub-channel kecil | Banyak client bisa kirim data bersamaan |
| **MU-MIMO** | AP ngobrol dengan banyak client sekaligus | Tidak ada yang nunggu giliran |
| **TWT** | Perangkat "tidur" sampai waktunya kirim | Hemat baterai HP dan IoT |
| **BSS Coloring** | "Warnai" BSS yang berbeda | Kurangi interferensi antar AP |
| **1024-QAM** | Modulasi lebih tinggi | Lebih banyak data per simbol |

**Analogi OFDMA:**  
Bayangkan channel WiFi seperti **jalan raya**. Di WiFi 5, hanya **1 mobil** yang bisa lewat dalam 1 waktu. Di WiFi 6, jalan raya dibagi jadi **banyak lajur**, dan **banyak mobil** bisa lewat bersamaan!

---

### 8.2. WiFi 7 (802.11be): "WiFi yang Super Cepat" ⚡

WiFi 7 adalah **generasi terbaru** (2024) dengan kecepatan hingga **46 Gbps**!

**Fitur Utama:**

| Fitur | Deskripsi | Benefit |
|-------|-----------|---------|
| **Multi-Link Operation** | Pakai 3 frekuensi sekaligus (2.4 + 5 + 6 GHz) | Kecepatan gila-gilaan, latency rendah |
| **320 MHz Channel** | Lebar channel 2x WiFi 6 | Lebih banyak data per waktu |
| **4096-QAM** | Modulasi sangat tinggi | Throughput ekstrem |
| **Multi-RU** | Resource unit lebih fleksibel | Efisiensi lebih baik |

**Analogi Multi-Link:**  
Bayangkan kamu punya **3 jalan tol paralel** (2.4 GHz, 5 GHz, 6 GHz). Di WiFi 6, kamu cuma bisa pakai **1 jalan tol**. Di WiFi 7, kamu bisa pakai **ketiganya sekaligus**! 🚗💨💨💨

## 9. Bab 8: WiFi di Rumah Kamu 🏠

### 9.1. Troubleshooting: Kenapa WiFi Lemot? 🐌

**Masalah 1: WiFi Lemot di Kamar**  
**Penyebab:** Sinyal lemah karena jarak atau halangan (tembok, furnitur).  
**Solusi:**  
- Pindahkan router ke tempat yang lebih tinggi dan terbuka  
- Pakai **WiFi extender** atau **mesh system**  
- Ganti ke **5 GHz** (lebih cepat, tapi jangkauan lebih pendek)

**Masalah 2: WiFi Sering Putus**  
**Penyebab:** Interferensi dari perangkat lain (microwave, bluetooth, router tetangga).  
**Solusi:**  
- Ganti channel ke **1, 6, atau 11** (untuk 2.4 GHz)  
- Pakai **5 GHz** (lebih sedikit interferensi)  
- Update firmware router

**Masalah 3: Banyak Perangkat, WiFi Lemot**  
**Penyebab:** Router kehabisan "napas" karena terlalu banyak client.  
**Solusi:**  
- Upgrade ke router **WiFi 6** (OFDMA, MU-MIMO)  
- Batasi bandwidth per perangkat (QoS)  
- Pakai **mesh system** untuk bagi beban

---

### 9.2. Tips Optimasi WiFi 🎯

1. **Pilih Channel yang Tepat:**  
   - 2.4 GHz: Pakai **1, 6, atau 11**  
   - 5 GHz: Pakai **36, 40, 44, 48** atau **149-165** (hindari DFS)

2. **Pisahkan SSID 2.4 GHz dan 5 GHz:**  
   - Beri nama berbeda (misalnya "RumahKu_2.4G" dan "RumahKu_5G")  
   - Pakai 5 GHz untuk perangkat yang butuh kecepatan (laptop, smart TV)  
   - Pakai 2.4 GHz untuk perangkat IoT (smart bulb, kamera)

3. **Update Firmware Router:**  
   - Cek website produsen router secara berkala  
   - Update untuk patch keamanan dan perbaikan bug

4. **Pakai Password yang Kuat:**  
   - Minimal 12 karakter  
   - Kombinasi huruf besar, huruf kecil, angka, dan simbol  
   - Jangan pakai kata yang mudah ditebak (nama, tanggal lahir)

5. **Matikan WPS:**  
   - WPS (Wi-Fi Protected Setup) punya celah keamanan  
   - Lebih baik setup perangkat secara manual

## 11. Bab 10: Peta Header C & Arsitektur Perangkat Lunak 🗺️

Sebelum kita mulai merakit frame dan menulis ribuan baris kode C di Dokumen 2 dan Dokumen 3, mari kita pahami dulu: **Mengapa bahasa C butuh file Header (`.h`)?**

### 10.1. Filosofi Header C: Buku Menu vs Dapur Restoran 🍳

Bayangkan sebuah restoran bintang lima:
- **File Header (`.h`)** adalah **Buku Menu**: Pelanggan (atau modul lain) cukup membaca menu untuk tahu makanan apa yang tersedia, apa bahan utamanya (parameter), dan berapa harganya (return value). Pelanggan tidak perlu tahu bagaimana koki memotong bawang atau mengatur api kompor.
- **File Source (`.c`)** adalah **Dapur Masak**: Di sinilah koki bekerja keras merebus kaldu, menggoreng daging, dan mencuci wajan (implementasi logika dan alokasi memori).

```
┌─────────────────────────────────────────────────────────────┐
│                 ARSITEKTUR HEADER (.h) vs SOURCE (.c)       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   📄 Header (.h)                💻 Source Code (.c)         │
│   "Buku Menu / Kontrak API"     "Dapur Masak / Logika"     │
│   ├── Deklarasi Struct          ├── Isi fungsi nyata        │
│   ├── Konstanta (#define)       ├── Loop & algoritma        │
│   └── Prototype Fungsi          └── Alokasi memori heap     │
│             │                               │               │
│             └─────────────┬─────────────────┘               │
│                           ▼                                 │
│                   ⚙️ Compiler (GCC)                         │
│                           │                                 │
│                           ▼                                 │
│                   📦 Binary Executable                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

Jika kamu mengubah resep bumbu rahasia di dapur (`.c`), buku menu (`.h`) tidak perlu dicetak ulang, selama nama menu dan porsinya tetap sama! Ini membuat sistem sebesar WiFi Pineapple tetap rapi, modular, dan bebas bug.

### 10.2. Peta 15 Header Bawaan Linux (Linux System & Socket Headers) 🐧

Untuk berbicara langsung dengan perangkat keras Wi-Fi (Raw Socket Layer 2) tanpa melalui protokol bawaan OS, kita menggunakan 15 header standar POSIX/Linux. Semuanya dibedah tuntas dengan source code di **[Dokumen 2](02_instruction_set.md)**:

| 14 | `<time.h>` | Penanggalan & stempel waktu (`time`, `localtime`, `strftime`) | Stempel tanggal otomatis loket pos | Mencatat detik tepat saat handshake atau probe request tertangkap |
| 15 | `<errno.h>` | Pelacakan kode error sistem (`errno`, `EINTR`, `strerror`) | Kode diagnostik rontgen sang dokter | Menangani socket terputus atau timeout secara elegan |
